# KimiK3-4G

A tiny launcher/distribution for the upstream **Kimi K3 in C** ultra-low-memory path.
It keeps the official full Kimi K3 checkpoint and exact routing/math, but defaults to
upstream's `ultra` execution profile so the inference process stays below a 4 GiB-class
RAM budget.

## What this is

- Full 2.78T Kimi K3 checkpoint; this is **not** a distilled/retrained model.
- Exact BF16/MXFP4 weights and all 93 layers.
- Embedding rows are streamed instead of keeping the 2.35 GB table resident.
- `lm_head` is projected in bounded streamed chunks instead of keeping 2.35 GB resident.
- Full-recompute mode reuses one recurrent-state slot.
- Trunk budget: **2.50 GB**.
- Expert-cache budget: **0.31 GB**.
- Upstream measured peak: **2.573 GiB RSS** on four complete one-token runs.

The trade-off is speed and storage. The official checkpoint plus packed trunk still needs
about **1.7 TB** of fast local storage. The upstream Jetson proof averaged about **949 s**
for one generated token. Treat this as proof-of-life / research mode, not interactive chat.

## Pinned upstream

This distribution pins:

- Repository: `FareedKhan-dev/kimi-k3-in-c`
- Commit: `117e9d29bde14db9742f54fb66a191fd0bf03903`
- Ultra feature introduced by commit: `b2f5b5bc6f1f575f6506e658299366b643dad053`

Pinning makes behavior reproducible and avoids silently pulling a future incompatible CLI.

## Quick start (Linux/macOS)

```bash
./scripts/bootstrap.sh

# after downloading the official checkpoint and preparing the packed trunk with upstream tools:
./scripts/run-4gb.sh \
  --model ~/k3model \
  --trunk ~/k3trunk \
  --tok ~/k3model \
  --prompt "The capital of France is" \
  --gen 1
```

## Windows: CMD / PowerShell / Windows Terminal

For a short copy/paste guide, see [`WINDOWS-QUICKSTART.md`](WINDOWS-QUICKSTART.md).

The Windows build is supported through **MSYS2 MinGW-w64**. You can start the build from
PowerShell, CMD, Windows Terminal, or directly from the MSYS2 MINGW64 shell.

> **Important for a 4 GB Windows PC:** Windows itself uses a significant part of physical
> RAM. Keep the Windows page file enabled, close browsers/IDEs before inference, and use a
> fast NVMe SSD. Upstream measured the Kimi K3 ultra inference process at about **2.57 GiB
> peak RSS**, but this repository does not claim that a physical 4 GB Windows machine was
> validated end-to-end. For a 4 GB host, treat this as research/proof-of-life mode.

### 1. Windows prerequisites

Install:

- **64-bit Windows 10/11**
- CPU with **AVX2 + FMA**
- **MSYS2** (default path recommended: `C:\msys64`)
- Around **1.7 TB free SSD space** for the official checkpoint + packed trunk
- Page file enabled; **8-16 GB** is recommended when the machine has only 4 GB physical RAM

Open **MSYS2 MINGW64** and install the build tools:

```bash
pacman -Syu
```

Restart the MINGW64 terminal if MSYS2 asks you to, then run:

```bash
pacman -S --needed git make mingw-w64-x86_64-gcc python
```

Check the tools:

```bash
git --version
make --version
gcc --version
python --version
```

### 2. Build from PowerShell / Windows Terminal

Open PowerShell in the extracted `kimik3-4gb` directory:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\bootstrap-windows.ps1
```

Use fewer or more build jobs if needed:

```powershell
.\scripts\bootstrap-windows.ps1 -Jobs 2
```

If MSYS2 is installed somewhere other than `C:\msys64`:

```powershell
.\scripts\bootstrap-windows.ps1 -Msys2Root "D:\msys64"
```

Expected executable after a successful build:

```text
upstream\bin\k3.exe
```

### 3. Build from CMD

Open CMD in the `kimik3-4gb` folder:

```bat
scripts\bootstrap.cmd
```

Or specify the MSYS2 path:

```bat
scripts\bootstrap.cmd -Msys2Root "D:\msys64" -Jobs 2
```

### 4. Build directly from MSYS2 MINGW64 terminal

```bash
cd /c/path/to/kimik3-4gb
bash scripts/bootstrap.sh
```

For example, if the project is at `D:\AI\kimik3-4gb`:

```bash
cd /d/AI/kimik3-4gb
bash scripts/bootstrap.sh
```

### 5. Prepare the model and trunk

The 4 GB launcher does **not** include the official Kimi K3 checkpoint. After bootstrap,
use the pinned upstream tools and follow the upstream **Full setup** instructions to:

1. Download the official checkpoint into a model directory, for example:
   `D:\AI\KimiK3\model`
2. Create the packed trunk, for example:
   `D:\AI\KimiK3\trunk`
3. Keep the tokenizer files in the model/tokenizer directory.

A typical Windows layout is:

```text
D:\AI\KimiK3\
├── model\          # official checkpoint + config/tokenizer files
└── trunk\          # packed trunk generated by upstream tools
```

Do **not** place the 1.56 TB model inside this Git repository.

### 6. Run from PowerShell / Windows Terminal

Recommended one-token proof-of-life command:

```powershell
.\scripts\run-4gb.ps1 `
  -Model "D:\AI\KimiK3\model" `
  -Trunk "D:\AI\KimiK3\trunk" `
  -Tok "D:\AI\KimiK3\model" `
  -Prompt "The capital of France is" `
  -Gen 1
```

Vietnamese prompt example:

```powershell
.\scripts\run-4gb.ps1 `
  -Model "D:\AI\KimiK3\model" `
  -Trunk "D:\AI\KimiK3\trunk" `
  -Tok "D:\AI\KimiK3\model" `
  -Prompt "Viết một câu chào bằng tiếng Việt" `
  -Gen 1
```

To keep CPU usage conservative:

```powershell
.\scripts\run-4gb.ps1 `
  -Model "D:\AI\KimiK3\model" `
  -Trunk "D:\AI\KimiK3\trunk" `
  -Tok "D:\AI\KimiK3\model" `
  -Prompt "Hello" `
  -Gen 1 `
  -Threads 2
```

The PowerShell launcher always forces:

```text
--preset ultra --ultra-low-memory
```

so the normal high-memory presets cannot accidentally be selected.

For a single line:

### 9. Prompt from a UTF-8 text file on Windows

For long prompts or Vietnamese text, a UTF-8 text file avoids command-line quoting issues.
Create `prompt.txt`, then run:

```powershell
.\scripts\run-4gb.ps1 `
  -Model "D:\AI\KimiK3\model" `
  -Trunk "D:\AI\KimiK3\trunk" `
  -Tok "D:\AI\KimiK3\model" `
  -PromptFile ".\prompt.txt" `
  -Gen 1
```

Raw token IDs are also supported:

```powershell
.\scripts\run-4gb.ps1 `
  -Model "D:\AI\KimiK3\model" `
  -Trunk "D:\AI\KimiK3\trunk" `
  -Ids "1,2,3" `
  -Gen 1
```

### 11. Check RAM while KimiK3 is running

PowerShell:

```powershell
Get-Process k3 | Select-Object Name,Id,
  @{N='RAM_GB';E={[math]::Round($_.WorkingSet64/1GB,2)}},
  @{N='Peak_GB';E={[math]::Round($_.PeakWorkingSet64/1GB,2)}}
```

Or open **Task Manager -> Details -> k3.exe** and enable the `Peak working set (memory)`
column.

### 12. Windows low-memory recommendations

For a machine with only 4 GB RAM:

- Keep **page file enabled**; do not disable virtual memory.
- Close Chrome/Edge, IDEs, Docker Desktop, WSL VMs and game launchers before inference.
- Start with `-Gen 1`.
- Keep `-Threads 2` initially.
- Prefer a fast **NVMe SSD**; ultra mode is strongly I/O-bound.
- Keep at least 10-15% free SSD space so Windows and the filesystem can operate normally.
- Do not enable `--incremental`, speculative decoding or draft models in the 4 GB profile.

If Windows kills the process or becomes unresponsive, increase the page file and/or use a
machine with 8 GB+ physical RAM. The ultra runtime lowers **process resident memory**; it
does not make Windows itself consume zero RAM.

## Download / prepare weights

This repository intentionally does **not** redistribute the 1.56 TB checkpoint.
Use the pinned upstream tools after bootstrap:

```bash
cd upstream
# Follow upstream README Full setup / download scripts.
# Then pack the trunk using the upstream packing script.
```

The launcher refuses settings that defeat the low-memory contract. In particular,
`--incremental`, `--spec`, and `--draft-trunk` are not exposed by `run-4gb.sh` because they
allocate additional carried state/KV or draft state.

## Memory contract

`run-4gb.sh` always invokes:

```text
--preset ultra --ultra-low-memory
```

and leaves generation in full-recompute mode. You can set prompt and generation length,
but short requests are strongly recommended because full recompute is intentionally traded
for lower RAM.

## Verify installation

```bash
./scripts/verify.sh
```

This checks the pinned commit, builds the weightless tests and asserts that the upstream
CLI still advertises the `ultra` preset. It does not download model weights.

## Why this repo is small

Rather than copying tens of MB of upstream code and losing provenance, this repository
contains only the 4 GB launcher, reproducible bootstrap and documentation. The source is
checked out at an exact upstream commit into `upstream/` locally. This keeps Apache-2.0
attribution clear and makes future upgrades reviewable as a single pinned-commit change.
